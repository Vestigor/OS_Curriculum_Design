1.Which other xv6 system call(s) could be made faster using this shared page? Explain how.
除了 getpid() 之外，其他只涉及读取内核中某些简单信息而无需进行写操作的系统调用，也可以借助共享的只读页面进行加速。其中较为典型的是获取父进程 ID getppid()和获取系统运行时间。
getppid() 的返回值是当前进程结构中已经存在的父进程 ID 字段，因此可以在 struct usyscall 中增加一个 ppid 字段，每次调度或 fork 时更新即可，从而允许用户程序直接通过共享内存访问该值，避免进入内核态。
同样，uptime() 本质是读取 ticks（时钟中断次数），该值在内核中不断更新，可以映射到该共享页的一个只读字段上，由内核定时更新用户空间可见的值，从而实现无系统调用读取当前时间。
此外，像 getuid() 等简单身份查询调用也具有类似特性，适合在共享页中以只读方式公开，使系统调用的调用路径从陷入内核转变为纯用户态内存访问，从而显著提升性能。

2.Explain the output of vmprint in terms of Fig 3-4 from the text. What does page 0 contain? What is in page 2? When running in user mode, could the process read/write the memory mapped by page 1? What does the third to last page contain?
vmprint() 输出的是进程页表的层级结构，遵循 RISC-V 的三层页表设计。最顶层是页目录（L2），每个条目指向中间页表（L1），而中间页表条目进一步指向页表（L0），L0 中每个条目最终映射一个物理页帧。
在实验示例输出中，“page 0” 表示第一级页表（L2）的第 0 项，该项有效，指向第二级页表（L1）。L1 的第 0 项同样有效，指向第三级页表（L0）。L0 的第 0、1、2 项分别映射有效物理页帧，即用户程序实际使用的前 3 页虚拟地址空间。也就是说，page 0 对应的是最上层页表项，它的有效项表示该地址空间中被使用的范围。
“page 2” 对应的是 L0 的第二个页表项，即用户程序虚拟地址的第三页。
“page 1” 也是 L0 中的页表项，映射的是用户空间的第二页。从页表项中提取的 PTE 权限位可以确定该页在用户态下是否可读写。若该 PTE 中包含 PTE_U 和 PTE_R，说明在用户模式下可读取；若同时包含 PTE_W，则可写。因此是否可读写要具体分析该页的 PTE 权限位。
“第三到最后一个页面”是指页表输出中倒数第三个有效叶子节点。在 xv6 中，倒数的几个映射通常对应 trampoline 或内核栈区域。但若该条目出现在用户页表，而不是内核页表，并且其物理地址落在内核段范围，它可能是共享的 trampoline 映射或用户访问不了的内核地址，通常设为只执行不可读写，用于用户态到内核态切换。通过页表权限位可以确认其不可访问性，验证其特殊用途。
