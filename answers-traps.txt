1. Which registers contain arguments to functions? For example, which register holds 13 in main's call to printf?
RISC-V 的调用约定规定函数参数通过寄存器 a0 到 a7（即 x10 到 x17）传递。
在 main 中调用 printf("%d %d\n", f(8)+1, 13)时，参数依次放入 a0、a1、a2。由汇编代码 24:	4635 li a2,13 可知，立即数 13 则放入 a2 寄存器。

2.Where is the call to function f in the assembly code for main? Where is the call to g? (Hint: the compiler may inline functions.)
在汇编文件 call.asm 中，main 函数没有对 f 或 g 的显式调用指令（即 jal f 或 jal g）。这是因为 f 和 g 都非常简单，编译器将它们内联到了调用处，直接计算了结果 f(8)+1 = 12，然后将其赋值给寄存器。因此它们的调用被优化掉，不会出现在汇编中。

3.At what address is the function printf located?
以下这段代码为跳转到printf对应位置：
34:	600080e7          	jalr	1536(ra) # 630 <printf>
由汇编代码可知 printf 函数的地址为 ra+1536，查看上一条汇编代码
30:	00000097          	auipc	ra,0x0
可知此时ra 的值即为0x30，因此 printf 函数的地址为0x30+1536=0x630。

4.What value is in the register ra just after the jalr to printf in main?
jalr指令的作用是把下一条指令的地址（即 PC + 4）保存在返回地址寄存器ra 中并跳转到指定地址。
根据jalr 指令的功能, 在刚跳转后ra 的值为pc+4=0x34+4=0x38.

5. Run the following code.
	unsigned int i = 0x00646c72;
	printf("H%x Wo%s", 57616, &i);      
What is the output? The output depends on that fact that the RISC-V is little-endian. If the RISC-V were instead big-endian what would you set to in order to yield the same output? Would you need to change to a different value?
%x 表示以十六进制格式输出整数 57616，即输出 e110；
%s 从地址 &i 开始，将连续内存解释为字符串（以 \0 结尾的字节序列）。i = 0x00646c72，对应16字节进制 00 64 6c 72，按小端存储顺序，其在内存中按顺序为 72 6c 64 00，分别对应'r'、'l'、'd'、\0，因此 %s 输出 "rld"。故最终输出为“He110 World”。
如果是大端系统，影响 %s 的输出，第一个存储的字节为 \0 ，因此输出时不会再输出其它字节，输出结果为“He110 Wo”。
为了得到和小端一样的 "rld" 输出，需要让内存中按顺序存储 72 6c 64 00，即令 unsigned int i = 0x726c6400。无需修改除i外的值。

6. In the following code, what is going to be printed after  'y='? (note: the answer is not a specific value.) Why does this happen?
	printf("x=%d y=%d", 3);
y 输出的是一个受调用前代码影响的“随机”值，因为 printf 根据格式字符串尝试读取两个整数参数，但程序只传入了一个。根据RISC-V ABI 规定，两个整数参数分别通过 a1 和 a2 传递，第一个参数 3 被正确传入 a1，但 a2 没有被设置，因此 printf 会从 a2 中取出一个未定义的值，用于第二个 %d，结果是随机的、不可靠的。
